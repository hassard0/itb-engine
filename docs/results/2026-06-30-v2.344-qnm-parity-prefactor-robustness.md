# v2.344 - How robust is the data-pinned parity window to the anomaly-inflow prefactor?

## Question

The program's most load-bearing -- and most-caveated -- result is the parity prediction: the constructed
theory needs `g_R2_parity > 0`, pinned from below by the cosmic-birefringence DATA and from above by the
gravitational anomaly-inflow budget `g_R2_parity^2 + 2 g_R3_parity^2 <= rho_inflow * g_4 * g_R2`. That upper
edge depends on `rho_inflow`, an O(1) prefactor. Does the parity result survive across the engine's OWN
declared plausible band for that prefactor, `anomaly_rho in [0.03, 0.12]`?

## Result (the sign/existence is robust; the magnitude is not -- with a quantified threshold)

The birefringence 2-sigma band is `g_R2_parity in [0.0471, 0.1529]` (lower edge `(0.34-0.18)/3.4`). The
anomaly upper edge is `sqrt(rho * g_4 * g_R2) = sqrt(rho * 0.10210)`. Scanning the declared band:

```text
   rho    anom_upper        joint window      width   0.06 survives?
  0.03      0.0553    [0.0471, 0.0553]       0.0082   False   <- band bottom
  0.0412    0.0649    [0.0471, 0.0649]       0.0178   True
  0.0525    0.0732    [0.0471, 0.0732]       0.0261   True
  0.06      0.0783    [0.0471, 0.0783]       0.0312   True    <- default
  0.075     0.0875    [0.0471, 0.0875]       0.0404   True
  0.0975    0.0998    [0.0471, 0.0998]       0.0527   True
  0.12      0.1107    [0.0471, 0.1107]       0.0636   True
```

Two closed-form thresholds:

- **window opens** iff `rho >= 0.0471^2 / 0.10210 = 0.0217` -- well *below* the declared band, so the joint
  window is non-empty and strictly positive at every `rho` in `[0.03, 0.12]`.
- **constructed 0.06 survives** iff `rho >= 0.06^2 / 0.10210 = 0.0353` -- *inside* the band.

So: across the engine's entire declared prefactor band, "parity violation is required, `beta = 0`
excluded" holds (the window is always non-empty and positive) -- the **qualitative headline is
prefactor-robust**. But the **specific value 0.06 is not**: in the lowest ~17% of the band, `[0.03,
0.0353)`, the constructed 0.06 would *violate* the anomaly budget and the window center shifts down to
~0.051. The closed-form edges match the engine's actual `GeneralizedAnomalyInflow` constraint exactly at
every grid point (a theory placed at the `sqrt(rho g_4 g_R2)` edge has anomaly margin 0). All 5/5 checks
pass.

## What this establishes

The honest sensitivity of the program's most load-bearing result. The parity headline you should trust is
**"`g_R2_parity > 0`, in `[0.047, ~0.08]`"** -- the *existence* and *sign* of the parity prediction are
prefactor-robust -- **not the single digit 0.06**, whose precise magnitude tracks the anomaly prefactor and
is contingent on `anomaly_rho` being near its default 0.06 rather than its declared floor. This stress-tests
(rather than re-asserts) the parity result, and reports its fragility with a quantified threshold.

## Honest scope

This is a sensitivity analysis of two constraints (cosmic_birefringence + generalized_anomaly_inflow), not
the full stack -- other constraints could only tighten the window, so these are UPPER bounds on the feasible
parity range. The anomaly budget's form and the birefringence map (`beta = 3.4 deg * g_R2_parity`) are the
engine's toy encodings; the thresholds (0.0217, 0.0353) are exact arithmetic *given* those forms but inherit
the toy-basis and O(1)-prefactor caveats. The `[0.03, 0.12]` band is the engine's own declared range, itself
a convention -- a wider band would enlarge the fragility region. The whole result still rests on the
cosmic-birefringence data being real (the ~3.6-sigma hint, v2.329 caveat); if it is a systematic, the lower
edge vanishes and parity becomes a soft direction with no positivity requirement. Toy basis, O(1)
prefactors.
