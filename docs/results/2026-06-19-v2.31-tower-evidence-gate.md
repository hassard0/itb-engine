**Date:** 2026-06-19
**Compute:** local run plus fresh Vulcan clone `~/codex-runs/itb-engine-main-v231a`
**Input:** v2.24 `TowerSpectrum` contract, v2.29 KK-radius adapter, v2.30 precision requirements

## Question

v2.30 made the KK-radius route precise. v2.31 asks:

> What evidence must accompany an adapter verdict before the engine may treat it as a
> framework-level quantum-gravity claim?

The answer is a provenance gate. Tower math and evidence provenance must both pass.

## Evidence Contract

`TowerEvidence` requires:

- `framework`
- `adapter_kind`
- `source_url`
- `source_type`
- `derivation_kind`
- `uncertainty_kind`
- `normalization_reference`
- a complete `TowerSpectrum`

Allowed source URL families are `https://arxiv.org/` and `https://doi.org/`. Allowed
source types are:

- `primary_literature`
- `computed_compactification`
- `validated_measurement`

## Interpretation

v2.31 adds the adversarial guardrail that was missing from the adapter path. A future
framework adapter must now clear two gates:

1. The two-sigma tower interval must sit on the excluding side of the critical tower
   threshold.
2. The adapter must carry source, derivation, normalization, and uncertainty provenance.

The defensible claim is:

> The engine now distinguishes mathematical tower exclusion from evidential claim
> readiness. The repo still has no non-synthetic evidence row for a registered framework,
> so there are no framework-level tower exclusions.

## Code changes

- `src/itb/tower.py` adds `TowerEvidence` and `validate_tower_evidence()`.
- `tests/test_framework_tower_spectrum.py` verifies complete and rejected evidence rows.
- `experiments/tower_evidence_gate.py` exercises math-only, overlap, and schema-ready
  fixture rows.
- `tests/test_tower_evidence_gate.py` locks the evidence/provenance guardrails.
- `experiments/results/v2.31/tower_evidence_gate.json` stores the verified artifact.

## Bottom line

The next real discriminator requires a non-synthetic `TowerEvidence` row. Without that
evidence, even a mathematically excluding adapter remains a readiness result, not a
quantum-gravity solution.
