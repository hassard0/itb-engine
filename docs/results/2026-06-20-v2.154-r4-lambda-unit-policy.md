## Symbolic Policy

The policy adds an executable symbolic overlay:

```text
policy_id = engine_r4_lambda_symbolic_alpha_prime_policy_v1
status = engine_convention_symbolic_nonclaiming
```

It preserves the two distinct normalization layers:

```text
raw K bridge:
K_Russo / shape = alpha_prime^3/(64*kappa^4)

post-pole R4 contact:
2*zeta(3)*alpha_prime^3*shape/(64*kappa^2)
```

The engine axis contract is symbolic:

```text
g_R4_ci = Lambda_R4^8 * c_i^(2)
```

For the v2.148 `string_tree_eft` shape packet, this gives:

```text
overall_R4_factor_symbolic =
  2*zeta(3)*Lambda_R4^8*alpha_prime^3/(64*kappa^2)

g_R4_c1 =
  zeta(3)*Lambda_R4^8*alpha_prime^3/(512*kappa^2)

g_R4_c2 =
  zeta(3)*Lambda_R4^8*alpha_prime^3/(512*kappa^2)

g_R4_c3 = 0
```

The `512` denominator is deliberate. It comes from the Bresciani matching
contract:

```text
c_plus = overall_R4_factor*K_plus/8
g_R4_c1 = g_R4_c2 = c_plus/2   when K_minus=0
```

## Guard Hardening

The base R4 projection guard now also blocks claim promotion for packets whose
normalization declares itself policy-scoped or claim-disabled. This closes a
bypass where a direct caller could attach a likelihood and
`discriminator_math = excludes_registered_framework` to the v2.148 policy packet.

New claim blockers for policy-scoped normalization:

```text
absolute_string_alpha_prime_normalization_missing
claim_use_not_allowed
engine_lambda_r4_unit_conversion_missing
k_convention_bridge_missing
policy_scoped_normalization_not_claimable
```

The generic guard-control packet can still pass the claim guard when it supplies
claim-shaped inputs. The new blockers apply when the packet itself declares that
its normalization is policy-scoped, symbolic, or not claimable.
