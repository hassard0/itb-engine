## What Changed

v2.202 converts pyRing's runtime imaginary-frequency coefficients into
linearized fractional damping-time deformation axes.

The source-backed formula is:

```text
pyRing:
tau_EFT = 1 / (1/tau_GR + gamma * domi_EFT)

linearized fractional tau deformation:
d((tau_EFT - tau_GR)/tau_GR)/d gamma at gamma=0
  = -tau_GR_dimensionless * domi_fit
```

The pyRing table convention is:

```text
domi_k = -om_i_k
```

because pyRing sign-flips the source table's `om_i` entries before using them
in `tau_EFT`.

Sources pinned by the artifact:

```text
https://git.ligo.org/lscsoft/pyring/-/tree/EFT_QNMs/pyRing/data/NR_data
https://git.ligo.org/lscsoft/pyring/-/blob/EFT_QNMs/pyRing/waveform.pyx
https://git.ligo.org/lscsoft/pyring/-/blob/EFT_QNMs/pyRing/initialise.py
```

## Claim Boundary

v2.202 resolves one narrow post-v2.201 subpiece:

```text
pyring_imaginary_frequency_to_parspec_tau_jacobian_defined
```

It does not resolve the operator-basis map. Remaining blockers:

```text
qnm_deformation_to_bresciani_engine_r4_map_missing
pyring_plus_minus_branches_not_independent_operator_axes
pyring_quartic_direction_to_bresciani_axis_orientation_missing
public_parspec_qeft_likelihood_or_posterior_samples_missing
claim_grade_systematics_export_missing
external_adversarial_review_missing
```

The correct claim is:

```text
The pyRing imaginary-frequency convention now has a source-backed conversion
into linearized fractional damping-time axes for the checked spin-zero table
slice.
```

The incorrect claim would be:

```text
pyRing now supplies a Bresciani engine-axis operator map, independent operator
columns, or a claim-ready ParSpec/qEFT likelihood.
```
