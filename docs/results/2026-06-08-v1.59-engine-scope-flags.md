# v1.59 — The engine now declares its own validity scope

**Date:** 2026-06-08
**Compute:** Vulcan.

---

## What this adds

v1.58 found that the engine's constraints only validly apply to local,
Lorentz-invariant frameworks. This operationalizes that into the engine itself so
it no longer silently returns verdicts it can't justify.

- `Framework` base now carries scope flags `local` and `lorentz_invariant`
  (default True). Hořava–Lifshitz sets `lorentz_invariant = False`; Causal Sets
  set `local = False`; all others remain in-scope.
- New `src/itb/scope.py`: `engine_validity(framework) -> ScopeVerdict` reports
  whether the amplitude-positivity / swampland constraints validly apply, and
  why not if they don't.

## Demonstration

```
string_tree_eft   in_scope=True   violations=[]
horava_lifshitz   in_scope=False  ['Lorentz invariance (assumed by positivity bounds)']
causal_set        in_scope=False  ['locality (assumed by the swampland program)']
```

A user (or a downstream analysis) running the engine on Hořava–Lifshitz or causal
sets now gets an explicit "OUT OF SCOPE — verdict not meaningful" flag rather than
a feasibility number that looks authoritative but isn't.

## Why it matters

This is the engine learning its own epistemic boundary. The realism program spent
much of its effort distinguishing robust conclusions from artifacts of toy
*numbers*; v1.58–59 add the complementary boundary — artifacts of applying
constraints outside their *assumptions*. The engine can now say, automatically,
"this framework is outside the regime where my bounds were derived; I decline to
adjudicate it." That honesty is exactly what separates a research instrument from
a verdict-dispensing oracle.

Tests: `tests/test_scope.py` (4 cases); full suite **388 passed**.

## Reproducibility

```python
from itb.scope import engine_validity
from itb.frameworks.horava_lifshitz import HoravaLifshitz
print(engine_validity(HoravaLifshitz()).note)
```
