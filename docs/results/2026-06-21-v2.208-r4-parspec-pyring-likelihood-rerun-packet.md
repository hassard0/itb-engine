## What Changed


## Output Contract

The likelihood export must provide at least one of:

```text
posterior samples
log-likelihood grid
```

The documented standard pyRing posterior path is:

```text
Nested_sampler/posterior.dat
```

The documented standard support outputs include:

```text
Nested_sampler/Evidence.txt
stdout_pyRing.txt
stderr_pyRing.txt
Nested_sampler/cpnest.log
Noise/
Plots/
```

The log-likelihood grid is not a documented pyRing CLI mode in the checked
public docs. Producing a grid requires a small driver that builds complete
runtime sample dictionaries and calls the configured model likelihood with an
explicit nuisance policy: fixed, profiled, marginalized, or posterior-reweighted.

and it must also provide:

```text
pyring_run_config
prior_specification
sampler_diagnostics
environment_lock
config_hash
output_hash_manifest
nonclaiming_coordinate_label
event_detector_strain_manifest
waveform_systematics_statement
```

The minimum sample schema is:

```text
paper_event
event_version
eft_direction
coordinate_scope
gamma_EFT_runtime
log_likelihood
log_prior
```

The minimum grid schema is:

```text
paper_event
eft_direction
gamma_EFT_runtime_grid
log_likelihood_grid
```

## Roadmap

The immediate next build is an executable config exporter that materializes the
12 pyRing runtime rerun rows into pyRing config files, hashes those configs, and
locks the environment. After that, run the sampler and export either posterior
samples or a log-likelihood grid in the same runtime coordinate scope.

The practical caveat is that no public production `.ini` files or archived
outputs were found for the EFT paper route. Until those are obtained or
recreated with pinned settings, the result is a compatible rerun recipe rather
than an exact reproduction claim.

The claim route still needs a separate source-backed qNM-to-Bresciani operator
map. If such a source is not found, the pyRing likelihood can still be useful as
a runtime-coordinate null test, but it cannot become a Bresciani-axis framework
discriminator.
