## Question

v2.20 found a nonredundant 9D tower gate, but it is not framework discrimination until
`phi_tower`, `m_tower`, or `Lambda_species` is assigned or measured. v2.21 translates
that gate into observable thresholds.

The question is:

> What tower observable would turn the v2.20 fiber restriction into an actual
> discriminator?

This remains a diagnostic roadmap, not a physical SDC solution and not a framework
exclusion.

## Interpretation

This turns v2.20 into a measurement target:

> The explicit tower axis becomes discriminating only if an observable constrains
> `phi_tower`, `m_tower`, or `Lambda_species`.

For the default toy model, the critical values are:

```text
phi_tower ~= 0.7433
m_tower   ~= 0.4755
Lambda_s  ~= 0.6500
```

The practical threshold is therefore simple: a robust lower bound
`m_tower >= 0.5` or an upper bound `phi_tower <= 0.693` keeps the allowed side of the
fiber; a measurement centered above `phi_tower ~= 0.75` rules out the default fiber.

This still does not rank named frameworks, because the framework encoders do not predict
`phi_tower`. v2.21 identifies the missing observable needed to make v2.20 useful.
