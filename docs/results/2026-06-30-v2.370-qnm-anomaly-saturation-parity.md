# v2.370 - SWING: anomaly matching (taken as the exact equality it is) predicts the parity magnitude -- and fits the data better

## Question (a swing in the sector the program wrote off as observational)

v2.364 concluded the parity coupling's existence, magnitude AND sign are all data-driven -- the theory
supplies only correlations. Is the *magnitude* really data-only, or does the theory force it?

## The swing

The engine's `GeneralizedAnomalyInflow` is an INEQUALITY (`g_R2_parity^2 + 2 g_R3_parity^2 <= rho g_4 g_R2`),
encoded conservatively. But its own docstring states the physics ("the total parity content must EQUAL the
inflow"), and anomaly matching ('t Hooft) is an **exact equality** in field theory -- a UV anomaly matches its
IR image exactly, not within a bound. So the physically-motivated case is **saturation**. With the verified
`g_R3_parity = 0` (v2.352), saturation fixes the parity coupling from the parity-EVEN sector, no data input:

```text
  g_R2_parity = sqrt(rho * g_4 * g_R2) = sqrt(0.06 * 0.529 * 0.193) = 0.0783
```

## Result (a theoretical parity value that fits better than the center)

```text
  anomaly-saturated g_R2_parity = 0.0783   (vs Chebyshev center 0.06)
  -> beta = 3.4 * 0.0783 = 0.266 deg,  0.82 sigma from measured 0.34 +/- 0.09
     center beta = 0.204 deg,  1.51 sigma      => saturation fits BETTER
  saturation sits exactly on the engine's anomaly-inflow boundary (margin 0) AND stays globally feasible
```

All 5/5 checks pass. The saturated value is the **upper edge** of the birefringence-allowed window
`[0.047, 0.078]` (v2.360), it sits exactly where the engine's anomaly margin vanishes, and it remains
feasible against the full stack.

## What this establishes

Anomaly matching gives a **data-independent reason to prefer the upper edge** of the parity window (0.078, not
the max-margin 0.06), and that preference **improves** agreement with the observed birefringence (0.82 vs 1.51
sigma). This refines the parity anatomy honestly: the SIGN is still data-set (v2.364 -- matching fixes
magnitude, not handedness), and the magnitude is DATA-BOUNDED into `[0.047, 0.078]` (v2.360), but *within* that
window the theory has a genuine theoretical **preference** -- the anomaly-saturated upper edge -- rather than
being a pure readout. So the parity coupling is **not entirely data-driven**: its magnitude has a field-theory
anchor (exact anomaly matching) that predicts a specific value *and* fits the data better than the geometric
center. A real, if modest, theoretical prediction in the sector the program had written off as purely
observational.

## Honest scope

DEFENSIBLE core: anomaly matching is an exact equality in field theory (not the engine's conservative `<=`),
so "the parity content saturates the inflow" is physically motivated, and it is verified to sit exactly on the
engine's anomaly boundary while staying globally feasible. CAVEATS: (1) the value 0.078 scales as `sqrt(rho)`
with the toy anomaly prefactor `rho = 0.06` (v2.344, load-bearing), so the NUMBER is toy even though the
STRUCTURE (parity fixed by the parity-even sector via matching) is not; (2) saturation assumes the parity
content is exactly `g_R2_parity^2 + 2 g_R3_parity^2` with `g_R3_parity = 0` and no other parity-odd operators
or fermion-loop contributions -- the engine's toy anomaly, not a computed one; (3) "fits better" is mild (0.82
vs 1.51 sigma, both within 2 sigma) -- a preference and a consistency, not a discrimination. It does NOT
overturn v2.364: the SIGN remains data-set, and the birefringence comparison presumes the detection is real
(v2.329). Robust content: exact anomaly matching gives the parity magnitude a theoretical anchor at the upper
edge of the data window, improving the fit -- so parity is not purely data-driven. Toy number, field-theory
structure.
