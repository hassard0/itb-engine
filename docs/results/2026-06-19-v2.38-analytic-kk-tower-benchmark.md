# v2.38 - Analytic KK tower benchmark: rates are enough, ownership is not

**Date:** 2026-06-19
**Compute:** local run plus fresh Vulcan clone `~/codex-runs/itb-engine-main-v238a`
**Input:** Aoufia/Castellano/Ibanez `2506.03253` and v2.25 tower thresholds
**Artifact:** `experiments/results/v2.38/analytic_kk_tower_benchmark.json`

## Question

v2.37 found a large-volume benchmark that crosses the tower threshold, but still lacks
framework-owned displacement and endpoint selection. v2.38 asks:

> Are analytic KK decompactification rates themselves large enough to cross the
> current tower threshold?

Yes. For `d = 4`, the scanned analytic KK vector norms all cross the threshold at
`Delta_moduli = 1`.

## Source

Primary source:

- Christian Aoufia, Alberto Castellano, and Luis E. Ibanez, "Laplacians in Various
  Dimensions and the Swampland", `arXiv:2506.03253`

The source gives the KK vector norm:

```text
|zeta_KK,p| = sqrt((d + p - 2) / (p * (d - 2)))
```

This audit uses it as `phi_tower = |zeta_KK,p| * Delta_moduli` for a benchmark
displacement, not as native framework evidence.

## Result

For `d = 4`, `p = 1..6`, and `Delta_moduli = 1`:

| candidate | `lambda_KK` | required `Delta_moduli` for exclusion |
|---|---:|---:|
| `d4_p1_kk_vector` | `1.224744871391589` | `0.6069034694928861` |
| `d4_p2_kk_vector` | `1.0` | `0.7433019116911739` |
| `d4_p3_kk_vector` | `0.9128709291752769` | `0.8142464481399377` |
| `d4_p4_kk_vector` | `0.8660254037844386` | `0.8582911176081254` |
| `d4_p5_kk_vector` | `0.8366600265340756` | `0.888415710226238` |
| `d4_p6_kk_vector` | `0.816496580927726` | `0.910355204239329` |

All six are benchmark-excluding at `Delta_moduli = 1`, but none are current framework
exclusions.

## Bottom line

The rate-size problem is solved for analytic KK decompactification benchmarks. The
remaining discriminator blocker is ownership: a framework must natively select the
decompactification endpoint and displacement before the engine can promote these
threshold-crossing rates to a framework exclusion.
