## Implemented Formulas

Ng native amplitude log-gain:

```text
v_ng(f) = kappa_Gpc_inv * D_C_Gpc * (f / 100 Hz)
```

Callister native SGWB amplitude log-gain:

```text
v_callister(f) = pi * (f / 100 Hz) * (kappa_z * z + kappa_D * D_C_Gpc)
```

Callister public-code SGWB energy-density hyperbolic argument:

```text
A_callister(f) = 2 * v_callister(f)
```

Both produce dimensionless source-native exponents. They do not produce
`g_R2_parity`, `g_R3_parity`, or a final PPV `beta_1` engine-normalized
likelihood.

## Interpretation

v2.64 moves the route from a formula specification to tested code for the
source-native amplitude exponent. It also separates Callister's waveform
log-gain `v_p` from the released SGWB likelihood/code convention that applies
`cosh(A)` and `sinh(A)` with `A=2v_p`. This gives the eventual posterior parser
a safe target that is not confused with an engine Wilson coefficient. It still
does not solve the physics mapping: helicity conventions, PPV `beta_1`
normalization, release-specific posterior ingestion, and engine-axis projection
remain open.

No quantum-gravity solution claim is available from this artifact.
