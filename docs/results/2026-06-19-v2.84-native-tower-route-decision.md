# v2.84 - Native tower route decision: direct source promotion retired

## Question

v2.83 found useful tower-like sources but no registered-framework native adapter.
This iteration turns that into a route decision so finite-range, positive-control,
conceptual, or wrong-framework tower sources cannot be accidentally promoted.

## Result


Claim-ready routes:

## Decisions

| route | decision |
|---|---|
| `quintic_single_compactification_direct_string_tree_promotion` | Retired for generic framework claims. |
| `string_positive_control_direct_exclusion` | Retired for framework exclusion; use only as guard positive control. |
| `asymptotic_safety_swampland_comparison_direct_tower` | Retired as native tower source; conceptual comparison only. |
| `horava_witten_to_horava_lifshitz_promotion` | Retired as wrong registered framework target. |
| `registered_native_tower_adapter_authoring` | Retained, required before any native tower claim. |
| `framework_specific_asymptotic_source_search` | Retained as a narrower future search route. |
| `native_tower_source_archive` | Retained as non-promoting design material. |

## Interpretation

The current native tower sources are useful but non-promoting. Direct promotion
of finite-range, positive-control, conceptual, or wrong-framework sources is
retired. The only live native route is a proper registered adapter with
source-owned endpoint, displacement, spectrum, and normalization.

That means the next frontier step should either find such a registered native
adapter, or pivot to the next ranked discriminator route.
