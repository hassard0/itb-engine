## Interpretation

v2.32 prevents the project from drifting into vague "not solved" language. The next
artifact needed for the tower discriminator is sharply identified:

> A sourced `TowerEvidence` row for one reference-feasible, in-scope framework.

For the current catalogue, the most direct targets are:

- `string_tree_eft`
- `asymptotic_safety`
- `cdt`
- the four `discovered_*` in-scope candidates
- `pure_gr` as a baseline/null tower case

The defensible claim is:

> The engine has a ready tower-discriminator pipeline and a provenance gate, but no
> registered framework currently supplies the native non-synthetic tower evidence required
> for a framework-level claim.

## Code changes

- `src/itb/frameworks/base.py` adds a default `tower_evidence()` hook.
- `tests/test_framework_tower_spectrum.py` verifies default absence of native tower
  evidence.
- `experiments/discriminator_frontier.py` classifies every registered framework by
  reference status, engine scope, native tower spectrum/evidence, and next required
  artifact.
- `tests/test_discriminator_frontier.py` locks the current frontier counts and guardrails.
- `experiments/results/v2.32/discriminator_frontier.json` stores the verified artifact.

## Bottom line

The next iteration should stop improving the generic adapter path and either source a
real `TowerEvidence` row or prove that no current registered framework can supply one
without changing the framework catalogue.
