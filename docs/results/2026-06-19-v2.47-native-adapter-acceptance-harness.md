# v2.47 - Native adapter acceptance harness: future adapters have a live gate

**Date:** 2026-06-19
**Compute:** local run
**Input:** v2.45 generic claim guard and v2.46 native ownership frontier
**Artifact:** `experiments/results/v2.47/native_adapter_acceptance_harness.json`

## Question

v2.46 showed that no live framework currently exposes native tower evidence. v2.47
asks:

> If a future framework does expose native tower evidence, will the real
> discriminator frontier route it correctly?

Yes. The harness temporarily registers synthetic `string_tree_eft` tower
adapters and runs the normal `diagnose_discriminator_frontier()` path.

## Result

```json
{
  "claim_ready_synthetic_fixtures": ["owned_scope_acceptance_fixture"],
  "generic_claim_blocked_synthetic_fixtures": ["missing_ownership_fixture"],
  "claimable_framework_exclusions_now": [],
  "registry_restored_after_harness": true
}
```

The owned-scope synthetic adapter has:

- excluding tower math
- promotion guard ready
- asymptotic source scope
- framework-owned endpoint metadata
- framework-owned displacement metadata

It reaches `tower_discriminator_claim_ready`.

The missing-ownership synthetic adapter has the same excluding spectrum but lacks
owned endpoint and displacement metadata. It remains
`tower_generic_claim_guard_blocked`.

## Bottom Line

The next real adapter does not need new frontier plumbing. It needs honest
source data. Once a registered framework supplies native owned tower evidence,
the live discriminator path will either mark it claim-ready or return a precise
guard blocker.
