## Audit Rows

| row | source-backed status | still blocked by |
|---|---|---|
| Ng `kappa` to Jenks `beta_1_0` | Jenks explicitly identifies the Ng distance/frequency dependence as encoded in `beta_1_0`. | No engine-owned Ng posterior parser, no harmonized helicity sign map, no engine-axis projection. |
| Callister waveform `kappa_D/kappa_z` | Callister maps `kappa_D` to the distance branch and `kappa_z` to the redshift branch. | Two-axis alpha/beta route, not a single `beta_1_0` likelihood; population sensitivity remains. |
| Callister public-code energy convention | The public code applies `cosh(A)`/`sinh(A)` with the `A=2v_p` energy-density argument. | Energy-density argument is not itself a waveform PPV beta parameter. |

## Interpretation

The strongest route is now clear: Ng is the closest source-backed candidate for
a Jenks `beta_1_0` amplitude-branch adapter. Callister is also source-backed,
but it is a two-parameter alpha/beta route plus a separate SGWB energy-density
implementation convention. Mixing those into a single beta likelihood would be
an error.

No `g_R2_parity`, `g_R3_parity`, or claim-ready PPV likelihood is produced.
