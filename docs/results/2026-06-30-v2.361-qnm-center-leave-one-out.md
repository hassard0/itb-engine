# v2.361 - Is the engine's central prediction well-posed? Leave-one-out stability of the Chebyshev radius (with a methodological caveat)

## Question

The method-as-proposal validation (the under-done third mandated direction). The engine's headline output is a
single constructed theory -- the Chebyshev center (max-min-margin point) of the consistent+observed region.
For that to be a meaningful PROPOSAL, the prediction must not hinge on any one constraint: does the central
prediction survive dropping individual constraints?

## Result (well-posed -- after fixing a methodological trap)

**The trap (an honest discovery).** A naive Chebyshev radius over ALL constraints is ill-defined, because the
engine's margins are not cross-comparable: the `gw_speed_bound` margin is `~5e-16` (its bound is itself 5e-16
in absolute units, v2.358) while theoretical margins are O(0.01-1) (tightest 0.020). So the all-constraint
min-margin is dominated by gw_speed's tiny absolute scale, and a naive leave-one-out is spuriously dominated
by "dropping gw_speed" -- an artifact (the first attempt gave exactly this degenerate result). *Any* program
computation that aggregates margins across constraints must restrict to comparably-scaled ones.

**The result** (data constraints kept for feasibility but excluded from the radius objective):

```text
  theoretical Chebyshev radius (full):  0.037
  drop bnossw_monogamy             [core]           radius += 0.006
  drop anomaly_cancellation        [core]           radius += 0.006
  drop generalized_anomaly_inflow  [core]           radius += 0.005
  drop t_hooft / graviton_fwd / swampland / disp-tower [core]  radius += 0.000
  drop scalar_positivity / HM-wedge / cubic-pos / EFT-box [slack]  radius += 0.000
  max core 0.006  vs  max slack 0.000   ->  no single drop blows it open (<< 0.5)
```

All 5/5 checks pass. The always-slack controls do not move the radius at all; only the anomaly/universality
family opens it, and only by `~0.006`. No single drop blows the prediction open.

## What this establishes

The engine's central prediction is **well-posed**: it is over-determined by a small theoretical core (the
anomaly/universality family) and **invariant** to dropping the slack remainder -- the well-posedness a
method-as-proposal needs. The engine's answer is a stable feature of the consistency geometry, dominated by
an identifiable handful (the v2.325 core), not balanced on one knife-edge condition. And the honest
by-product -- the engine's signed-distance margins are not cross-comparable (gw_speed's 5e-16 scale) -- is a
real caveat for any program computation that aggregates margins (a min, a gradient-normalized worst-margin):
it must restrict to comparably-scaled constraints.

## Honest scope

The methodological caveat (margins not cross-comparable) is exact and important. The radius itself is found
by a seeded annealed random ascent -- a LOCAL search, not a proved global optimum -- so the radius and the
increases are estimates/lower-bounds; a better optimizer could raise any radius, which would only sharpen the
slack-vs-core separation if the full radius rose too. "Radius" is in the engine's mixed theoretical-margin
units and the 0.02 "meaningful" threshold is conventional; the robust content is the SEPARATION (slack ~0 vs
core opening it) and that no single drop explodes it, not the absolute numbers. The core/slack sets are from
v2.325's sample-based tally; the cosmic-birefringence DATA constraint (a v2.325 core member) is necessarily
excluded from the radius objective here by the scale issue, so this validates the THEORETICAL core's
well-posedness (the data constraints' role is in v2.358). Conditional on the full (screened) stack + toy
basis. Toy basis, O(1) prefactors.
