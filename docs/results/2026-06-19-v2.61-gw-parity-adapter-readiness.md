# v2.61 - GW parity adapter readiness: public likelihood material is not an engine map

## Question

v2.60 found that existing GW parity papers contain real constraints but no
claim-ready packet for `g_R2_parity` / `g_R3_parity`. This audit asks a sharper
question: do any public releases already provide enough material to build the
source-side likelihood, and if so, what is still missing before engine-axis
promotion?

## Result

The important improvement over v2.60 is that two source-side routes are now
actionable as non-promoting loaders:

- Ng et al. publish a reproducible GWTC-3 amplitude-birefringence paper
  repository and Zenodo data release.
- Callister et al. publish code, data, and documentation for the SGWB
  stochastic-birefringence analysis.

Neither is an engine-normalized `g_R2_parity` / `g_R3_parity` likelihood.

## Blockers

No screened route currently supplies all of:

- source-backed operator map into the engine basis;
- dimensional conversion from the paper parameter to dimensionless engine axes;
- frequency normalization matching the engine `omega0` convention;
- public likelihood or posterior in the mapped basis;
- framework-exclusion math in ITB normalization.

The existing `LIGOBirefringenceBound` remains a legacy toy constraint. It must
not be treated as an external claim-ready likelihood.

## Interpretation

The next useful implementation is not direct promotion. It is a native or PPV
intermediate packet, followed by a source-backed operator-normalization
concordance before any engine projection:

```text
ng:kappa_Gpc^-1_at_100_Hz
callister:kappa_D
callister:kappa_z
jenks:ppE_or_parameterized_parity_basis
```

Only after that concordance exists should a non-promoting source-side loader for
the Ng GWTC-3 `kappa` release or the Callister SGWB `kappa_D`/`kappa_z` release
be projected toward `g_R2_parity` / `g_R3_parity`.

No quantum-gravity solution claim is available from public code/data alone.
