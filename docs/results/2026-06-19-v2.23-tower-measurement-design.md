## Question

v2.22 showed that framework exclusions depend on how `phi_tower` is assigned. v2.23 asks:

> Which mock tower observations would actually reduce that assignment ambiguity?

The answer is useful but limited. Direct `phi_tower` intervals and strong tower-mass
floors can eliminate assignment scenarios, but no observation in this audit creates a
claimable framework exclusion while the unassigned scenario remains viable.

## Result

Top incremental measurement designs:

| measurement | newly ruled-out scoreable scenarios | total survivor reduction | post-measurement survivor range |
|---|---:|---:|---:|
| `phi_interval_0.75_pm_0.05` | 3 | 36 | `0..1` |
| `phi_interval_0.55_pm_0.05` | 3 | 34 | `0..3` |
| `mass_floor_0.8` | 1 | 27 | `0..5` |
| `phi_interval_0.25_pm_0.05` | 0 | 15 | `0..10` |
| `phi_upper_0.4` | 0 | 4 | `0..10` |

The strongest clean mass-floor candidate is:

```json
{
  "label": "mass_floor_0.8",
  "newly_ruled_out_scoreable_scenarios": ["low_phi_all"],
  "measurement_reduced_scoreable_scenarios": [
    "curvature_plus_parity_strong",
    "curvature_ranked_moderate",
    "curvature_ranked_strong",
    "low_phi_all"
  ],
  "claimable_framework_exclusions": []
}
```

By contrast, the weaker threshold `m_tower >= 0.5` does not reduce any scenario that
was alive before the measurement:

```json
{
  "label": "mass_floor_0.5",
  "newly_ruled_out_scoreable_scenarios": [],
  "measurement_reduced_scoreable_scenarios": [],
  "ruled_out_scoreable_scenarios": ["near_threshold_all"],
  "claimable_framework_exclusions": []
}
```

That matters because `near_threshold_all` was already dead under the explicit tower
cutoff. The measurement confirms the conflict but does not add discrimination among
surviving assignment scenarios.

## Model-crisis measurements

Two direct high-phi intervals leave no evaluated assigned scenario with a reference-feasible
survivor:

- `phi_interval_0.95_pm_0.1`
- `phi_interval_1.2_pm_0.1`

These are not clean discriminators. They should be treated as stress tests of the tower
model, the EFT cutoff choice, or the assignment scenario portfolio.

## Interpretation

v2.23 sharpens the next experimental target:

1. Direct `phi_tower` measurements near `0.55` or `0.75` are maximally discriminating
   among the current assignment scenarios.
2. A strong tower mass floor, roughly `m_tower >= 0.8` in this normalization, is the
   cleanest mass-only discriminator.
3. The commonly tempting `m_tower >= 0.5` threshold is not enough to move the surviving
   scenario set.
4. Every candidate still reports `claimable_framework_exclusions: []`.

The defensible claim is therefore:

> Tower observations can turn the assignment problem into an experimental design problem,
> but framework-level quantum-gravity exclusions still require a framework-specific tower
> prediction or a measurement tied to the realized framework.

## Code changes

- `experiments/tower_measurement_design.py` evaluates tower-mass floors, phi upper
  bounds, and measured phi intervals against v2.22 assignment scenarios.
- `tests/test_tower_measurement_design.py` locks the guardrail that measurements reduce
  assignments, not framework claims.
- `experiments/results/v2.23/tower_measurement_design.json` stores the verified artifact.

## Bottom line

The loop has moved from "does the tower axis matter?" to "what must be measured to use
the tower axis?" The next bottleneck is explicit framework-level tower spectra or a
direct observable that maps a realized framework into `phi_tower`.
