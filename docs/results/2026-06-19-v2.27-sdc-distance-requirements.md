## Question

v2.26 found qualitative SDC sources but no actionable `TowerSpectrum`. v2.27 asks:

> If a future adapter uses `m_tower / m0 = exp(-lambda_sdc * Delta)`, what moduli
> distance would it have to supply to clear the v2.25 tower thresholds?

This converts the literature seed into a concrete adapter target without pretending that
the current framework encoders already provide `Delta`.

## Interpretation

v2.27 makes the next adapter job precise. A compactification-level adapter cannot simply
say "there is an SDC tower"; it must provide a moduli displacement and uncertainty. For
the d=4 sharpened slope, a one-sigma `phi_tower` uncertainty of `0.05` maps to:

- exclusion only if `Delta > 1.1926`,
- allowance only if `Delta <= 0.9098`,
- no claim in the overlap zone between those values.

The defensible claim is:

> SDC literature can be converted into quantitative adapter requirements, but without a
> framework-specific `Delta_moduli` there are still no framework-level tower exclusions.

## Code changes

- `tests/test_sdc_distance_requirements.py` verifies the dimension-dependent slope math
  and the no-framework-claim guardrail.

## Bottom line

The tower path is now narrowed to a concrete missing datum: a sourced compactification
or framework adapter must provide `Delta_moduli` with uncertainty tight enough to land
outside the overlap zone.
