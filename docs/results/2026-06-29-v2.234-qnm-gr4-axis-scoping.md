# v2.234 - Scoping a Riemann^4 (g_R4) axis: the positivity-mandated bridge to the core engine

## Question

v2.233 showed the ringdown-active curvature operator is the quartic Riemann invariant (dim-8,
"`g_R4`"), one order beyond the engine's Ricci-scalar curvature basis (which stops at `g_R3`). What
would a `g_R4` axis carry if added to the engine -- and is there a verifiable bridge between the
17-cycle ringdown thread and the core engine's positivity logic? (Read-only -- no change to the
committed constraint stack.)

## Result

Extending the engine's EXISTING positivity/causality machinery one order up the curvature ladder, a
`g_R4` axis would carry a definite set of constraint types:

```text
gr4_positivity              g_R4 >= 0                          (dispersion_tower g_2n>=0 analog)
curvature_dispersion_tower  g_R3^2 <= g_R2 * g_R4              (g_6^2<=g_4*g_8 analog)
curvature_forward_dominance g_R3 >= c * g_R4   (c ~ O(1))      (graviton_forward_positivity analog)
spin6_positivity            g_R4 enters the J=6 partial wave   (spin_four_positivity next J)
cemz_higher_causality       |g_R4| <= kappa * (matter*curv)    (cemz_causality higher order)
```

The verifiable bridge -- the **curvature dispersion tower forces a nonzero Riemann^4**:

```text
g_R4 >= g_R3^2 / g_R2

  framework           g_R2     g_R3     g_R4_min forced     mandated
  pure_gr             0.00     0.00       0.000               no  (no curvature corrections)
  string_tree_eft     0.20     0.15       0.1125              yes
  asymptotic_safety   0.15     0.10       0.0667              yes
  cdt                 0.22     0.15       0.1023              yes
  lqg_induced         0.30     0.30       0.3000              yes
```

**The engine's own positivity logic does not merely ALLOW the ringdown-active operator -- it
REQUIRES it.** Every known framework with curvature corrections (4/5) is forced by the curvature
Cauchy-Schwarz tower to carry a nonzero Riemann^4 coefficient, at a level set by its lower curvature
couplings. That forced operator is exactly the ringdown-active one (v2.233). This is the structural
bridge: the ringdown thread studies an operator that the core engine's dispersion tower mandates.

## What this establishes

A concrete, verifiable connection between the 17-cycle ringdown thread and the core Wilson engine:
the dimension-8 Riemann^4 operator that drives black-hole ringdown is positivity-MANDATED by the
engine's own dispersion-tower logic (`g_R4 >= g_R3^2/g_R2`), not an optional add-on. It also
specifies exactly what a `g_R4` axis extension would carry (5 constraint types from existing
machinery), turning the v2.233 "bridge needs a `g_R4` axis" conclusion into an actionable spec.

## Honest scope

READ-ONLY scoping -- this does NOT modify the committed constraint stack (still 38 constraints); it
specifies what a `g_R4` axis WOULD carry. The bound forms use representative O(1) prefactors (set to
1), exactly as the existing curvature/matter constraints do (their docstrings flag the same); the
literal coefficients need the Gegenbauer / partial-wave evaluation. The forced `g_R4_min` is a
relative (dimensionless) statement in the toy basis; the absolute `g_R4` normalization that would
connect it to a physical ringdown bound stays un-sourceable (the v2.215 / Bresciani-axis-map
blocker). Actually adding the axis + constraints to the engine is a separate, dedicated effort.
Parity-odd `g_R4_c3` stays dark (v2.209).
