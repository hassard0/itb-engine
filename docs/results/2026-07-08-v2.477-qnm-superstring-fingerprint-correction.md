# v2.477 - superstring correction to v2.476: the exact-string fingerprint match is amplitude-dependent, not established

v2.476 executed the exact fingerprint for the **bosonic** Veneziano amplitude Γ(−s)Γ(−t)/Γ(−s−t), whose forward
residues telescope to flat (|r_n| = 1) → a_k = ζ(k) → double-ratio 1.232, matching the candidate's 1.322 to ~7%.
But the bosonic open string is **tachyonic** and is not the heterotic gauge sector. The physically-relevant amplitude
is the open **superstring** (GSO-projected), whose Veneziano factor carries a SUSY shift:

```text
  A_susy = K(s,t) * Gamma(-s) Gamma(-t) / Gamma(1 - s - t)     (K = t_8 F^4 kinematic prefactor)
```

The Γ(1−s−t) (vs bosonic Γ(−s−t)) changes the forward residues from flat to **r_n = 1/n** (verified numerically:
1, ½, ⅓, ¼, …). So the bare-factor superstring moments are a_k = ζ(k+1) and the low double-ratio is

```text
  zeta(3) zeta(5)/zeta(4)^2 = 1.064
```

which the candidate's 1.322 matches only to **~24%** — far worse than the bosonic 1.232 (~7%). 5/5 checks pass.

## Two corrections to v2.476

1. The candidate matched the **bosonic (tachyonic, unphysical)** string better than the physical superstring, so
   v2.476's "exact match to a real string amplitude to ~7%" **overstated** — the real (super)string value is 1.064,
   ~24% off.
2. Even 1.064 is only the **bare Γ-factor**; the physical superstring gauge amplitude has a kinematic prefactor
   K ~ t_8 F⁴ (not computed) that shifts the effective moments further. So the physical fingerprint isn't cleanly
   pinned — the prefactor bookkeeping is exactly the error-prone step flagged all along.

## Honest final status

The scale-clean fingerprint **test** is executable (v2.464–466), and the flat-residue result is an exact fact about
the *bosonic* Veneziano Γ-factor (v2.476) — but the **physically-relevant superstring fingerprint is different**
(1.064 bare, plus an uncomputed prefactor) and does **not** cleanly match the candidate. The exact-string match is
**amplitude-dependent and not established**, an open item — v2.476's headline is retracted/tempered.

This does **not** say the candidate is string-*inconsistent*: 1.064 vs 1.322 is a bare-factor mismatch with the
prefactor uncomputed and the candidate's 1.322 carrying the g_6=g_8 Chebyshev artifact, so the comparison is simply
not clean either way. The still-robust content: the double-ratios are scale-independent (v2.464), the candidate's
tower is multi-state/string-like in *shape* (v2.438/v2.466), and the heterotic identification rests on its **other**
supports (the rigorously-required R², the parity/Green–Schwarz argument). A fast honest self-correction on the heels
of the bold v2.476 swing.
