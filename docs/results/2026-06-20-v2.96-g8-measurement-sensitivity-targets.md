## Sensitivity Targets

The scan uses registered framework `g_8` coefficients, engine scope gating, and
reference-stack feasibility. It is a one-dimensional Gaussian proxy; any real
claim would still require the v2.93 intake gate fields: public likelihood,
covariance, closed systematics, and EFT-domain bounds.

| item | value |
|---|---:|
| Registered frameworks | 13 |
| Eligible for current `g_8` target | 8 |
| Eligible exact `g_8` degeneracies | 0 |
| Tightest eligible pair | `string_tree_eft` vs `discovered_data_driven` |
| Tightest eligible separation | `0.004` |
| Required total sigma for 2-sigma separation | `< 0.002` |
| Widest eligible single-axis target | `discovered_high_g8` |
| `discovered_high_g8` nearest eligible neighbor | `discovered_data_driven` |
| `discovered_high_g8` 2-sigma total-sigma target | `< 0.074` |

All registered exact degeneracies are still recorded:

| `g_8` | frameworks | status |
|---:|---|---|
| `0.3` | `asymptotic_safety`, `causal_set` | `causal_set` is out of engine scope. |
| `0.4` | `group_field_theory`, `lqg_induced`, `string_tree_eft` | `group_field_theory` and `lqg_induced` are reference-stack infeasible. |

## Interpretation

This does not solve the discriminator problem. It fixes the next actionable
piece: a future real `g_8` packet must beat a total uncertainty of `0.002` to
resolve every currently eligible single-axis target, or can use the
target-specific thresholds if the result is centered near one framework.

The blocker is now more precise:

```text
real_engine_normalized_g8_packet_missing
```

with a numeric minimum precision target attached.
