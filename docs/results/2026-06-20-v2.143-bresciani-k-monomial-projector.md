# v2.143 - Bresciani K monomial projector

## Question

v2.142 specified the source-backed K-factor rederivation route, but a future
derived or OCR-ingested K expression still needs a mechanical way to extract
`K_plus` and complex `K_minus`.

Can the engine project spinor-helicity monomial coefficients onto the Bresciani
helicity families without manually interpreting the result?

## Controls

The synthetic control has usable numeric components:

```text
K_plus = 0.3
K_minus = 0.1 + 0.05 i
overall_R4_factor = 8.0
```

But it is rejected:

```text
blockers = [source_backed_derivation_missing]
```

The source-backed shape control feeds the v2.139 inversion:

```text
g_R4_c1 = 0.2
g_R4_c2 = 0.1
g_R4_c3 = 0.05
positivity passed = true
```

The malformed control is rejected for asymmetric family coefficients and
inconsistent conjugacy.

## Interpretation

The future K-factor path is now more mechanical. If OCR/library access or an
independent polarization derivation yields source-backed coefficients for these
monomial families, the engine can extract `K_plus/K_minus`, verify symmetry and
conjugacy, and feed the Bresciani R4 coordinate inversion. No source formula has
been supplied yet, so this is not a physics claim.
