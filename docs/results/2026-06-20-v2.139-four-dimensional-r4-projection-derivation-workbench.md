## Matching Contract

The Bresciani target channels are now encoded as a matching contract:

```text
same_helicity_to_same_helicity -> 8*c_plus
helicity_flip_complex_channel -> 8*c_minus
conjugate_helicity_flip_channel -> 8*conjugate(c_minus)
```

The source contact ansatz is:

```text
A_R4 = overall_R4_factor * K_R4
```

If a future source-backed derivation supplies normalized source components, the
workbench uses:

```text
c_plus      = overall_R4_factor * K_plus / 8
Re(c_minus) = overall_R4_factor * Re(K_minus) / 8
Im(c_minus) = overall_R4_factor * Im(K_minus) / 8
```

Then it inverts:

```text
g_R4_c1 = (c_plus + Re(c_minus)) / 2
g_R4_c2 = (c_plus - Re(c_minus)) / 2
g_R4_c3 = Im(c_minus)
```

## Interpretation

The downstream algebra is no longer ambiguous. The remaining hard work is the
source-backed decomposition of the string kinematic factor `K_R4` into the
Bresciani same-helicity and complex helicity-flip monomial families in a fixed
four-dimensional frame. Once that is supplied, the workbench can compute
`c_plus`, `c_minus`, `g_R4_c1/c2/c3`, and positivity diagnostics.
