## Route Outcomes

```text

```

It has the qNM deformation schema and Bresciani K-to-engine projection, but it
does not supply:

```text
qnm_deformation_to_operator_coordinate_map
operator_coordinate_to_bresciani_K_map
finite_3x4_sensitivity_matrix

```

The pyRing/Cano plus Bresciani route has local branch-column rank:

```text
route = pyring_quartic_tables_plus_bresciani_dictionary
local matrix shape = 6 x 4
local matrix rank = 4
```

That rank is in pyRing QNM branch coordinates, not Bresciani operator
coordinates. The graph therefore explicitly forbids:

```text
rank_only_branch_projection
label_overlap_as_operator_identity
synthetic_qnm_to_K_matrix
published_bound_surrogate_as_likelihood
```

The Bresciani-only route is a downstream projection:

```text
route = bresciani_amplitude_dictionary_only
local matrix shape = 3 x 3
local matrix rank = 3
```

It maps `K_plus/Re(K_minus)/Im(K_minus)` to engine axes, but it has no qNM edge.

The best executable next route is:

```text
route = pyring_eft_likelihood_rerun_route
kind = next_likelihood_build_candidate
```

This is not a Bresciani sensitivity source. It is a nonclaiming path toward a
reproducible likelihood export in pyRing runtime coordinates.
