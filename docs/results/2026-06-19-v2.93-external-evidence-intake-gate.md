# v2.93 - External evidence intake gate: executable rejection path

## Question

v2.92 defined packet contracts for retained external routes. This iteration asks
whether those contracts can be enforced by executable intake logic before any
future discriminator promotion.


## Gate Behavior

| packet | result |
|---|---|
| Synthetic complete `g_8` packet | Schema-ready, non-claimable because it is synthetic. |
| Incomplete `g_8` packet | Rejected for missing fields, likelihood, and normalization. |
| Native tower packet missing ownership | Rejected for missing ownership metadata. |
| Unknown route packet | Rejected because no contract exists. |

## Interpretation

The intake gate is executable. It can distinguish schema-complete fixtures from
real claim evidence and rejects unknown, incomplete, or route-rejected packets
before discriminator promotion.
