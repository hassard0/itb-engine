# v2.57 - Birefringence prediction non-circularity: no source-backed beta prediction yet

## Question

v2.56 showed that the cosmic-birefringence route needs a source-backed adapter
from observed `beta` to the engine parity axes. This audit asks which registered
frameworks predict beta independently of the beta input, and which only match it
because the measurement was used to construct the framework.

## Result

Artifact: `experiments/results/v2.57/birefringence_prediction_noncircularity_audit.json`

Current route status:

```text
no_non_circular_source_backed_beta_prediction
```

Current claim-ready frameworks:

```text
none
```

The audit screened all 13 registered frameworks under the current toy map:

```text
beta_pred_deg = 3.4 * g_R2_parity
```

Independent toy-map matches within 2 sigma:

- `group_field_theory`
- `horava_lifshitz`
- `lqg_induced`

Data-driven toy-map matches within 2 sigma:

- `discovered_data_driven`

## Why No Claim Follows

Every framework is blocked by:

- `missing_source_backed_beta_adapter`
- `not_claim_ready`

Additional blockers:

| blocker | count |
|---|---:|
| `beta_prediction_not_within_hint_band` | 9 |
| `framework_fails_current_stack` | 3 |
| `prediction_reuses_beta_input` | 1 |

The independent toy-map matches are not claim-ready:

- `group_field_theory`, `horava_lifshitz`, and `lqg_induced` match beta only
  under the engine's toy normalization;
- all three fail the current exact stack point evaluation used here;
- none has a source-backed beta adapter.

The `discovered_data_driven` row matches beta under the toy map, but it uses beta
as a construction input. It cannot validate the same beta measurement.

Parity-even catalogued frameworks such as `pure_gr`, `string_tree_eft`,
`asymptotic_safety`, `cdt`, `causal_set`, and `emergent_gravity` predict beta
zero under the toy map and therefore miss the current beta hint.

## Interpretation

The birefringence route remains empirically interesting, but it cannot yet pick a
quantum-gravity framework. Matching the beta hint is not enough. A claim needs:

- a source-backed beta-to-parity adapter;
- a framework prediction independent of the beta measurement;
- stack-compatible framework status;
- exclusion math against registered alternatives.

No current framework satisfies that package.
