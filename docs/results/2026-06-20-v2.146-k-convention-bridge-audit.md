## Candidate Audit

The raw pole-match candidate uses:

```text
Russo:   A4 = kappa^2 K A4^0
Russo:   A4^0 = 1/(sbar*tbar*ubar) + 2*zeta(3) + ...
Russo:   sbar = alpha_prime*s/4
Kallosh: M_tree(1-,2-,3+,4+) = shape/(kappa^2*s*t*u)
```

With `alpha_prime = 1`, the pole term gives:

```text
K_Russo / shape = 1/(64*kappa^4)
```

This identifies the convention issue, but it is not an acceptable K bridge:

```text
bridge_depends_on_kappa_convention
bridge_not_dimensionless_against_shape
amplitude_normalization_conventions_not_unified
```

The unit shape bridge remains useful as an internal control:

```text
K_Russo / shape = 1
```

but it is rejected as a source-backed bridge because it is an engine convention,
not a primary-source K formula.

## Interpretation

The supergravity pole comparison cannot be used to silently normalize the string
R4 packet. It produces a bridge proportional to `kappa^-4`, which means the
Russo and Kallosh amplitude normalizations have not been unified into the
dimensionless K bridge required by v2.145.
