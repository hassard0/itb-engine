# v2.22 - Tower framework scenarios: exclusions are assignment-dependent

**Date:** 2026-06-19
**Compute:** local run plus fresh Vulcan clone `~/codex-runs/itb-engine-main-v222a`
**Input:** v2.20 explicit tower model and v2.21 observable thresholds
**Artifact:** `experiments/results/v2.22/tower_framework_scenarios.json`

## Question

v2.21 identified concrete tower-observable thresholds, but named framework encoders still
do not predict `phi_tower`. v2.22 asks:

> If we assign `phi_tower` by explicit scenarios, do any framework exclusions become
> robust?

The answer is no. Exclusions appear in some scenarios, but none is robust across all
assignment assumptions.

## Scenarios

The experiment evaluates:

- `unassigned`: no framework has a tower coordinate,
- `low_phi_all`: every framework assigned `phi_tower = 0.25`,
- `near_threshold_all`: every framework assigned `phi_tower = 0.75`,
- `curvature_ranked_moderate`: coefficient-load ranking with max `phi_tower = 0.70`,
- `curvature_ranked_strong`: coefficient-load ranking with max `phi_tower = 1.20`,
- `curvature_plus_parity_strong`: curvature plus parity ranking with max `phi_tower = 1.20`.

These are scenario assumptions, not framework predictions.

## Interpretation

v2.22 prevents a premature claim. The explicit tower coordinate can discriminate, but
framework-level conclusions are entirely controlled by the `phi_tower` assignment.

The defensible claim is:

> The tower axis is a real new diagnostic dimension, but no named framework is robustly
> excluded until `phi_tower` is independently predicted or measured.

The next useful work is therefore not another arbitrary assignment scenario. It is one of:

1. add framework-specific tower-coordinate predictions from actual model structure,
2. identify an observable that measures or bounds `phi_tower`,
3. extend framework encoders to include tower spectra instead of only Wilson coefficients.
