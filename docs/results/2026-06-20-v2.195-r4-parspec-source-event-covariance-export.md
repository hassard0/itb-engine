# v2.195 - R4 ParSpec source-event covariance export

## Question

Can the v2.194 source-event topology likelihood export event-specific and
combined nuisance-marginalized R4 covariance for the ParSpec source events,
without promoting the route to a framework claim?

## What Ran

The artifact reads the v2.194 event-topology likelihood and the v2.191
ParSpec/qEFT source-asset audit. It exports covariance rows directly from the
actual v2.194 nuisance-marginalized likelihood grids for the ParSpec source
events:

```text
GW150914-v3:
  detectors = H1, L1
  grid_points = 125
  nuisance_points_per_detector = 81, 81

GW200129_065458-v1:
  detectors = H1, L1, V1
  grid_points = 125
  nuisance_points_per_detector = 81, 81, 81
```

It also builds a combined source-event grid by summing the aligned
log-marginal likelihood and profile likelihood values over the shared
`g_R4_c1/g_R4_c2/g_R4_c3` coefficient grid.

The export is still based on the coarse nuisance grid inherited from v2.194.
It is a deterministic covariance export and blocker split, not a posterior
sampler.

## Malformed Control

The diagnosis includes a malformed-control packet that corrupts the first
event covariance and the combined grid count. The evaluator rejects it with:

```text
GW150914_covariance_not_psd
GW150914_covariance_shape_unexpected
combined_event_set_covariance_grid_missing
```

This prevents a missing or malformed covariance packet from silently clearing
the blocker.

## Claim Boundary

The correct claim is:

```text
The engine now exports source-event and combined covariance from the actual
v2.194 ParSpec source-event topology likelihood grids.
```

The incorrect claim would be:

```text
The engine has produced a claim-grade ParSpec/qEFT R4 posterior or framework
exclusion.
```

No framework exclusions are claimable from this artifact.
